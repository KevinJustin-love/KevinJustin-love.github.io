具身智能中的强化学习：从 Sim-to-Real 到 DiffusionNFT

从经典 RL、Sim-to-Real、Diffusion Policy 到 Flow-GRPO 与 DiffusionNFT · 更新至 2026-09-12

先建立一个直觉

强化学习可以看成“让控制器通过试错学会做事”。机器人看到相机画面和自身状态，这些信息组成 state；控制器输出 action，例如关节速度或夹爪开合；环境执行动作后返回下一个状态和 reward。一段连续交互叫作 trajectory。RL 真正要学的是 policy：在不同状态下，哪些动作会让未来的总回报更高。

具身任务比图像生成更难，因为动作会真实改变世界。图像模型可以一次生成很多候选图片并评分；机器人每次探索都要消耗时间，还可能碰撞、磨损或需要人工重置。因此真实机器人 RL 往往是“示范/离线预训练 + 少量在线改进”，而不是从零开始盲目探索。

发展主线

  1. 经典 RL 与控制。 Q-learning、actor-critic、policy gradient 和 PPO 解决值函数估计、策略更新和稳定性问题，但仍受奖励设计和样本效率限制。
  2. 深度 RL 与 Sim-to-Real。 通过并行仿真、域随机化、系统辨识和残差控制，把昂贵探索移到仿真，再用少量真实数据校准接触、摩擦、视觉噪声和延迟。
  3. 离线 RL 与示范学习。 从遥操作、专家示范和历史 rollout 学习，降低真实探索风险；代价是数据覆盖不足，以及策略可能选择数据中没有验证过的动作。
  4. 真实世界数据飞轮。 自动重置、失败过滤、并行机器人和持续收集数据逐渐与算法同等重要。DexFlyWheel 和 RL-100 代表了“预训练策略 → 真实反馈 → 数据筛选 → 再训练”的系统路线。
  5. 扩散策略与 VLA。 Diffusion Policy 把 action chunk 当成条件生成对象，能表达多个合理的动作模式；OpenVLA、X-DiffVLA 等工作进一步把视觉、语言和动作统一起来。

Flow-GRPO：为什么扩散模型需要特殊的 RL

GRPO 对同一个条件采样一组结果，用组内相对奖励决定哪些结果应该被加强。Flow-matching 模型通常由确定性 ODE 采样，缺少传统 policy gradient 所需的随机探索和逐步概率。Flow-GRPO 将 ODE 转为保持边际分布的 SDE，使每个去噪步骤具有可用于 RL 的随机转移，再把最终生成质量反馈给整条采样轨迹。

直观地说，它先问“同一个 prompt 生成的哪张图更好”，再沿生成路径追问“哪些去噪步骤促成了这个结果”。这条路线有效，但需要保存或重建反向采样轨迹，并处理 solver、概率比和信用分配。

DiffusionNFT：把奖励变成 forward-process 更新

DiffusionNFT（Diffusion Negative-aware Fine-Tuning）提出直接在 forward diffusion / flow-matching 过程中优化。它把生成结果按奖励分为正样本和负样本，用二者的预测误差构造隐式的策略改进方向。相比 Flow-GRPO，它更少依赖完整反向轨迹、似然估计和特定采样器，并强调可以使用黑盒 solver。

迁移到机器人时，可以把 clean image 对应为 action chunk，把图像奖励对应为成功率、距离、碰撞和能耗，把正/负图像对应为成功/失败 rollout。但这只是迁移假设：机器人动作是带动力学约束的长时序，必须重新解决时间信用分配、动作连续性、安全过滤和 sim-to-real。

我会怎样判断“迁移成功”

不能只看图像生成的 GenEval 或偏好分数。一个具身迁移实验至少应在相同采样预算和奖励函数下比较行为克隆、轨迹级 RL 与 forward-process/NFT 风格更新，并报告未见初始位姿上的成功率、碰撞率、动作平滑度、数据效率和跨 embodiment 泛化。
